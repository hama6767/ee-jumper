# 実装方針とデモの選び方

## 推奨: まず泳ぐ

最初の成果を小さく作るなら、Jumperの既存の運動学を維持し、各リンクへの簡易流体力で
泳ぎ方を探索する構成が適しています。MuJoCoの標準の楕円体流体モデルを使うと、
独自の流体ソルバを実装する必要がありません。密度・粘性・抗力・揚力を調整できます。

カーテンでは、薄い布の接触、引張・曲げ特性、把持時の滑り、手を離してつかみ直す順序が
絡みます。接触解決が重くなるだけでなく、失敗時に布モデルと方策のどちらを直すべきか
切り分けにくくなります。成功時だけ報酬を与える設定では探索も難しくなります。
MuJoCoのflexを使うことはできますが、初回デモとしての費用対効果は遊泳を下回る、という判断です。

これはエンジニアリング上の判断です。泳ぎ方より「カニがつかんで登る」という見せ方を
優先する場合には、剛体の棒や固定ホールドに対象を限定すると有力な代案になります。

## 物理

物理刻み1 ms、制御周期20 ms（50 Hz）、MuJoCo `implicitfast`。
元の22関節に位置サーボ（kp=3 N·m/rad、kv=0.08 N·m·s/rad）を追加し、
トルクは±2 N·mに制限しています。これは簡易サーボであり、電圧・温度・速度に依存する
実機モーター特性は再現しません。

流体力は `fluidshape="ellipsoid"` と `fluidcoef` で各衝突geomに設定します。
標準係数は blunt drag=0.5、slender drag=0.25、angular drag=1.5、
Kutta lift=1.0、Magnus lift=1.0。密度1000 kg/m³、粘性0.001 Pa·s。
流速はMuJoCoの `wind` へ世界座標で指定します。
速度に対する二次抵抗や揚力などの計算はMuJoCoの実装に委ねます。
MuJoCo自身の付加質量関連項も含まれますが、流場・後流を解くCFDではありません。

浮力は各リンクの `body.gravcomp` としてモデル内に設定します。
比率は `water.density × buoyancy_ratio / 1000`、標準値は1です。
これにより重力を残したまま、各物理ステップでリンク重心への浮力が発生します。
描画同期が消去する `xfrc_applied` には依存せず、リセットしても中性浮力を維持します。

```text
V_i = buoyancy_ratio × m_i / 1000
F_b,i = −rho × V_i × gravity
```

`V_i` は仮定した排水体積です。衝突メッシュ体積の和ではありません。
そのまま足し合わせると重なる形状で体積を二重計上するため、
最初はリンクごとの中性浮力という明確な仮定を採用しました。
各リンク重心の浮力に加え、全体浮心を重心から機体+Zへ10 mmずらした復元偶力を胴体に加えます。
`step_water`が各物理ステップで `r_CB × F_b` を計算します。並進の合力は変わらず、yawの保持もしません。
復元トルクは関節のPD制御ではなく、浮力の位置エネルギーに由来します。
抵抗・揚力の楕円体にも重なり・遮蔽・流体干渉の近似誤差があるため、
実機に進む前に体積・流体係数・浮心を測定して置き換える必要があります。

参照:
[MuJoCo Fluid forces](https://mujoco.readthedocs.io/en/stable/computation/fluid.html)。

## 学習

### 最初の段階: CEM

関節を毎ステップ自由に探索する代わりに、左右対称の周期運動を13変数で記述します。
共有周波数1変数と、前・中・後肢の各組の振幅2変数、曲げの位相差、組の位相です。
候補を試し、スコアの高い上位25%から次の候補分布を更新します。
初回から状態フィードバックを持つニューラルネットワークを学習するより小さく始められます。

これは方策パラメータのブラックボックス最適化であり、PPOのような深層強化学習ではありません。
学習済みJSONにはseed・物理設定・世代ごとのスコア・比較用の静止結果・
学習に使わなかった3つの初期状態seedの評価を保存します。
同一の流体設定だけで評価するため、これだけで頑健性を主張しません。

### フィードバック制御: PPO

Gymnasium環境は22次元の正規化目標関節角を受け取り、ホーム角から最大±0.65 radを指令します。
関節の物理的な範囲でもクリップします。
観測は関節角22、関節角速度22、胴体速度6、上方向3、前進方向3、深度誤差1、前回アクション22。
カメラ画像や特権的な流体力は入力していませんが、速度・姿勢はノイズなしの真値です。

報酬は全体重心の前進距離を主項とし、横速度、向き、姿勢、深度、
アクチュエータの絶対機械仕事、アクションの変化に罰則を付けています。
全体重心を使うことで、胴体を脚に対してずらすだけの動きを前進と数えにくくしています。
不安定化、転倒、深度逸脱、移動範囲超過で終了し、時間上限ではtruncateします。

`scripts/train_ppo.py` は導入用ベースラインです。
300,000ステップという既定値は収束の保証ではありません。
最初はplanarで学習し、次にfreeで姿勢・深度制御を含めて再学習します。
その後、流体係数±20%、流速、浮力、初期姿勢をランダム化する順序を推奨します。
流体ランダム化・カリキュラム自動遷移は今後の拡張で、現在は未実装です。

### PPOの再生

```python
from stable_baselines3 import PPO
from ee_jumper.env import SwimEnv

env = SwimEnv(mode="planar", render_mode="human")
policy = PPO.load("runs/ppo")
obs, info = env.reset(seed=100)
try:
    while True:
        action, _ = policy.predict(obs, deterministic=True)
        obs, reward, terminated, truncated, info = env.step(action)
        if terminated or truncated:
            break
finally:
    env.close()
```

## カーテンクライミングへ進む場合

1. **固定ホールド**: 脚・爪の到達可能範囲を調べ、接触と高さ報酬を検証。
2. **明示的な把持拘束**: ホールド近傍、爪の閉鎖、相対速度、荷重上限を条件として
   把持/解除する簡易モデル。現実の摩擦把持とは区別する。
3. **柔らかい支持物**: ホールドをばねで支持し、揺れに対する制御を追加。
4. **小さい布**: MuJoCoの2D `flexcomp` で粗い布を作り、上端を固定。
   伸び・曲げ・摩擦・接触厚み・時間刻みを、方策学習の前に単体検証。
5. **布の把持**: つまみ接触を解くか、近傍の布節点との破断可能な拘束で近似するか選ぶ。
   節点の瞬間移動や離れた布をつかめる実装は避ける。

参照:
[MuJoCo Deformable objects](https://mujoco.readthedocs.io/en/stable/modeling.html#deformable-objects)。
このクライミング環境は今回実装していません。
